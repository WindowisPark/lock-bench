Key Insights

  • 커넥션 풀 분리만으로 Lock Bleed 해소 불가 (p95 개선 3%, 목표 500ms 대비 22배)
  • Routing DataSource는 정상 작동 — write-pool / read-pool 별도 초기화 확인
  • 병목이 HikariCP가 아닌 InnoDB: 200개 트랜잭션이 동일 row에 SELECT FOR UPDATE를 연쇄로 걸면서 MySQL lock manager 자체에 부하 발생
  • 근본적 해결책: (1) Redis 분산락으로 전환하여 DB 커넥션 미점유, (2) CQRS + 읽기 레플리카, (3) 서로 다른 productId로 분산
